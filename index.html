CM

A dashboard that publishes layouts,
and the app that renders them.

Both read one component registry, so a screen looks the same in the editor and on a phone. Layouts live in Postgres and are resolved per user, per tenant, per feature flag — changing one needs no release.

Design dashboard

Eight tabs: overview, studio, library, assignments, paths, app data, features and rules. The studio has 42 components, 49 section presets, 15 screen templates, 7 visual styles and 11 palettes.

Best on a desktop

The app

Renders whatever layout the database resolves for you, reads real tasks, projects and notes, and writes back when you tick something. Falls back to a built-in layout when nothing is assigned.

Best on a phone

Reading it without an account

The dashboard runs against seeded sample data in the browser — open it and everything works, nothing is saved anywhere.

The app needs a sign-in, because what it shows you is decided by row-level security in the database. Without credentials you will see the sign-in screen, which is the honest answer rather than a fake one.

A design can also be reviewed with no account at all through a preview link — /app/?preview=<token> — which renders one specific draft, read only, and is never counted as usage.
