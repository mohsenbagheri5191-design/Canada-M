Server-driven UI

A dashboard that publishes layouts,
and the app that renders them.

Both read one component registry, so a screen looks the same in the editor and on a phone. Layouts live in Postgres and resolve per user, per tenant, per feature flag — changing one ships without a release.

Design dashboard

Overview, studio, library, assignments, paths, app data, features and rules. The studio carries 42 components, 49 section presets, 15 screen templates, and 7 visual styles that each restyle a whole design at once.

How a screen reaches a phone

DesignCompose a screen in the studio and publish a version.
AssignBind that version to a user, an organisation, or everyone.
ResolveOne database function picks the layout and returns the trace explaining why.
RenderThe app draws it from the same registry the studio drew it with.

What you will see

Dashboard
Runs against seeded sample data in your browser. Everything works — publish a version, roll one back, change a theme — and nothing is saved anywhere.
The app
Asks you to sign in, because what it shows is decided by row-level security in the database. Without credentials you get the sign-in screen, which is the honest answer rather than a fabricated one.
Preview links
A draft can be reviewed with no account at all: app/index.html?preview=<token> renders one specific version, read only, and is never counted as usage.
